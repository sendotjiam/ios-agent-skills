# Instruments Profiling, SQL Tracing & SQLite WAL Diagnostics

Diagnosing performance regressions and subtle concurrency bugs in Core Data and SwiftData requires combining runtime debug flags, Xcode Instruments profiling templates, and SQLite WAL inspection.

---

## 1. Xcode Launch Arguments

Set these flags in your Xcode Scheme (`Edit Scheme... -> Run -> Arguments -> Arguments Passed On Launch`):

| Launch Argument | Level | Purpose |
|---|---|---|
| `-com.apple.CoreData.ConcurrencyDebug 1` | Critical | **Asserts on any cross-thread context violation.** Crashes immediately with a backtrace on unconfined reads or writes. |
| `-com.apple.CoreData.SQLDebug 1` | Basic | Logs every SQL statement generated by Core Data to the Xcode Console. |
| `-com.apple.CoreData.SQLDebug 2` | Detailed | Logs SQL statements plus bind variables and query execution time in seconds. |
| `-com.apple.CoreData.SQLDebug 3` | Deep Dive | Logs full SQL statements, bind values, query durations, and row data snapshots. |
| `-com.apple.CoreData.MigrationDebug 1` | Migration | Detailed logs during lightweight and custom schema migrations. |
| `-com.apple.CoreData.CloudKitDebug 1` | CloudKit | Verbose sync logs for `NSPersistentCloudKitContainer`. |

---

## 2. Interpreting SQL Tracing Output

With `-com.apple.CoreData.SQLDebug 3`, examine the Xcode debug output:

```sql
CoreData: sql: SELECT 0, t0.Z_PK, t0.Z_OPT, t0.ZNAME, t0.ZCREATEDAT FROM ZITEM t0 WHERE t0.ZSTATUS = ? 
CoreData: annotation: sql connection: 0x600003b55a00
CoreData: annotation: db has 250000 rows
CoreData: annotation: total fetch execution time: 0.0845s for 20 rows.
```

### Warning Signs in SQL Output:
1. **Repeating identical queries**: Repeated `SELECT ... WHERE Z_PK = ?` indicates an active N+1 query loop / fault thrashing.
2. **Missing `LIMIT` clause**: A `SELECT` statement returning thousands of rows without `LIMIT 20` indicates missing `fetchBatchSize`.
3. **Table Scans**: Slow query times (>0.05s) on queries with `WHERE` clauses indicate missing SQLite indexes on the filter properties.

## 3. Profiling with Xcode Instruments

Launch Instruments via **Product -> Profile -> Core Data**:

### Key Instruments:
1. **Faults**: Measures the rate of fault fires. Healthy apps show low, flat fault rates during scrolling; steep upward staircases during UI interaction indicate fault thrashing.
2. **Fetches**: Displays the volume of fetch requests executed per second. Ensure heavy fetches occur on background queues.
3. **Saves**: Monitors the frequency and duration of `context.save()` operations. Frequent single-record saves degrade flash storage longevity and block queues.

## 4. SQLite WAL Mode & Storage Footprint

Both Core Data and SwiftData use SQLite's **WAL (Write-Ahead Logging)** mode by default. You will see three files in the application sandbox:
- `App.sqlite` (Main database)
- `App.sqlite-wal` (Write-ahead log)
- `App.sqlite-shm` (Shared memory index)

### Diagnosing WAL Runaway Growth
If `App.sqlite-wal` grows to tens or hundreds of megabytes:
- A background thread or query is holding an open read transaction, preventing SQLite from checkpointing WAL frames into the main database file.
- Uncommitted transactions are lingering in unclosed contexts.

Ensure background contexts are transient or call `context.reset()` after completing batch transactions to allow automatic checkpointing to proceed.
